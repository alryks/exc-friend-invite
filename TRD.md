# TRD: Mattermost Bot для акции "Приведи друга"

## 1. Цель

Реализовать в текущем проекте Mattermost-бота для акции "Приведи друга": пользователь должен видеть уже отправленные анкеты кандидатов, создавать новую анкету, прикладывать документы кандидата и отправлять анкету в внешний backend через Friend API.

Проект должен быть готов к развертыванию в окружении, где Mattermost сможет вызывать публичные webhook URL бота. Локальная проверка полного сценария через Mattermost может быть невозможна без публичного адреса, поэтому реализация должна быть подготовлена к запуску в Docker Compose и описана в документации по деплою.

Аутентификацию и авторизацию пользователей на этом этапе не реализовывать. В текущем режиме функционал доступен всем пользователям Mattermost.

## 2. Текущая база проекта

Проект уже содержит каркас `mmpy_bot`:

- точка входа: `src/bot/main.py`;
- конфигурация через `pydantic-settings`: `src/bot/config.py`;
- пример plugin с обработчиками сообщений, interactive message actions и Interactive Dialogs: `src/bot/plugins/base.py`;
- Dockerfile сервиса бота: `src/bot/Dockerfile`;
- `docker-compose.yml`;
- Swagger-контракт Friend API: `swagger-snp-back.json`.

Нужно заменить примерный функционал на production-like реализацию акции, сохранив стек Python + `mmpy_bot`.

## 3. Внешние интеграции

### 3.1 Mattermost

Бот работает как пользователь Mattermost через `mmpy_bot`. Настройки подключения Mattermost читаются стандартным способом `mmpy_bot` из переменных окружения.

Обязательные Mattermost возможности:

- личное сообщение `!start` для открытия главного меню;
- interactive message buttons для действий в сообщениях;
- Interactive Dialogs для ввода полей анкеты;
- webhook endpoints бота для получения button action и dialog submit событий;
- чтение сообщений с вложенными файлами на шаге загрузки документов;
- скачивание файлов из Mattermost через REST API бота.

Официальная документация Mattermost по Interactive Dialogs указывает, что диалог открывается через `POST /api/v4/actions/dialogs/open` после получения `trigger_id`. В этом проекте диалог нужно открывать из interactive message action, так как единственный пользовательский триггер бота - личное сообщение `!start`. Dialog submission приходит на URL интеграции и содержит `user_id`, `channel_id`, `team_id`, `state`, `callback_id`, `submission`, `cancelled`.

В Interactive Dialogs поддерживаются элементы `text`, `textarea`, `select`, `bool`, `radio`, `date`, `datetime`. Поле загрузки файла в списке поддерживаемых элементов отсутствует, поэтому документы кандидата нельзя загрузить напрямую в Interactive Dialog. Загрузку документов нужно делать отдельным шагом через обычные сообщения Mattermost с вложениями.

Источники:

- https://developers.mattermost.com/integrate/plugins/interactive-dialogs/
- https://developers.mattermost.com/integrate/reference/message-attachments/

### 3.2 Friend API

Все запросы к Friend API выполняются методом `POST`.

Base URL задается переменной окружения `FRIEND_API_BASE_URL`, например `http://host:port` без завершающего slash.

Аутентификация Friend API:

- заголовок `X-API-KEY: <FRIEND_API_KEY>`;
- `FRIEND_API_KEY` задается в `.env`;
- если ключ не задан, сервис должен стартовать только в явном mock/dev режиме, иначе завершаться с понятной ошибкой.

Friend API endpoints:

| Endpoint | Назначение |
| --- | --- |
| `POST /create_app` | Создать пустую анкету. Возвращает `status=ok`, `application_id`. |
| `POST /get_app` | Получить анкету по `application_id`. |
| `POST /set_app` | Обновить поля анкеты. |
| `POST /delete_app` | Удалить анкету. |
| `POST /add_app_photo` | Добавить фото/документ к анкете в base64. |
| `POST /clear_app_photo` | Очистить документы анкеты. |
| `POST /get_app_photo` | Получить PDF документов анкеты: `pdf_base64`, `pdf_url`. |
| `POST /get_user_apps` | Получить анкеты пользователя по `tg_id`. Для Mattermost использовать стабильный числовой surrogate id, описанный ниже. |
| `POST /get_jobs` | Получить список вакансий. |
| `POST /get_facility_binds` | Получить привязки объектов к именам пользователей. На текущем этапе не использовать для ограничения доступа. |

Для взаимодействия с backend создать отдельный клиент, например `src/bot/friend_api.py`, с таймаутами, retries для временных сетевых ошибок и единым форматом ошибок.

## 4. Идентификатор пользователя

Backend ожидает поле `user_id`/`tg_id` числового типа. Mattermost `user_id` является строкой.

Требование: реализовать стабильное преобразование Mattermost user id в положительное 63-bit число:

```python
int.from_bytes(hashlib.sha256(mm_user_id.encode("utf-8")).digest()[:8], "big") & ((1 << 63) - 1)
```

Этот surrogate id использовать:

- в `get_user_apps` как `tg_id`;
- в `set_app.data.user_id` при финальной отправке анкеты.

В сообщениях пользователю не показывать surrogate id.

## 5. Данные анкеты

Анкета отправляется в Friend API через `set_app` в поле `data`.

Обязательные поля:

- `job`: объект вакансии целиком из `get_jobs`;
- `referral`: ФИО рекомендателя;
- `name`: ФИО кандидата;
- `gender`: `Мужской` или `Женский`;
- `phone`: российский телефон в нормализованном виде или пустая строка;
- `age`: дата рождения в формате `YYYY-MM-DD 00:00:00`;
- `date_on_object`: дата прибытия на объект в формате `YYYY-MM-DD 00:00:00`;
- `residence`: одно из `Россия`, `Беларусь`, `Киргизия`, `Казахстан`;
- `comment`: строка, может быть пустой;
- `user_id`: Mattermost surrogate id пользователя;
- `submitted`: `true` при финальной отправке.

Дополнительные поля, приходящие из `get_app`, сохранять при частичных обновлениях, если они не конфликтуют с обновляемыми значениями.

Статусы:

- если `status` отсутствует и `submitted` отсутствует, это черновик/новая анкета;
- если `status=accepted`, показывать "Принята";
- если `status=declined`, показывать "Отклонена";
- если `submitted=true`, но `status` отсутствует, показывать "Отправлена";
- неизвестные статусы показывать как "Статус: <value>".

## 6. Пользовательские сценарии

### 6.1 Главное меню

Единственный пользовательский триггер:

- личное сообщение боту с текстом `!start`.

Бот должен обрабатывать только личные сообщения. Сообщения из публичных и приватных каналов, групповых чатов и тредов вне личного диалога нужно игнорировать, кроме webhook-событий от собственных interactive message buttons и Interactive Dialogs, если они относятся к уже открытому личному сценарию пользователя.

Ответ бота: ephemeral или обычное сообщение с текстом:

```text
Акция "Приведи друга"
Вы можете добавить нового кандидата или посмотреть ранее отправленные анкеты.
```

Кнопки:

- `Добавить кандидата`;
- `Список кандидатов`.

### 6.2 Просмотр списка кандидатов

При нажатии `Список кандидатов`:

1. Получить `applications = POST /get_user_apps {"tg_id": surrogate_user_id}`.
2. Если список пуст, показать сообщение "У вас пока нет отправленных кандидатов" и кнопки `Добавить кандидата`, `Назад`.
3. Если список не пуст, показать пост со страницей списка.

Формат элемента списка:

```text
<статус>: <ФИО кандидата>
<объект> - <должность>
```

Кнопки:

- по одной кнопке на анкету: `Открыть: <ФИО>`;
- пагинация `Назад`/`Далее`, если анкет больше размера страницы;
- `В главное меню`.

Размер страницы: 5 анкет.

При открытии анкеты:

- получить актуальные данные через `/get_app`;
- показать карточку анкеты;
- если есть документы (`photo_ids` непустой или `photo_pdf` задан), запросить `/get_app_photo` и приложить ссылку `pdf_url`; если `pdf_base64` есть, можно загрузить PDF в Mattermost и прикрепить к сообщению, но ссылка достаточно приемлема для первой версии.

Редактирование отправленных анкет:

- разрешить редактирование только если анкета еще не финализирована: нет `submitted` или `status=declined`;
- для `accepted` и отправленных без финального статуса показывать только просмотр.

### 6.3 Создание кандидата

При нажатии `Добавить кандидата`:

1. Получить список вакансий через `/get_jobs`.
2. Отфильтровать вакансии:
   - брать только вакансии с `удаленный_подбор == true`, если поле присутствует;
   - на текущем этапе не ограничивать по объектам/доступам пользователя.
3. Открыть Interactive Dialog для ввода анкеты.

Так как Interactive Dialog имеет ограничение длины option values и display names, значение `job` в select не должно содержать весь JSON вакансии. Нужно хранить список вакансий во временном state/cache и в `select` передавать короткий id, например индекс или hash. В `state` диалога сохранить `flow_id`, `user_id`, `channel_id`.

Рекомендуемый dialog title: `Новый кандидат` (до 24 символов).

Поля dialog:

| Поле | Type | Name | Обязательность | Правила |
| --- | --- | --- | --- | --- |
| Вакансия | `select` | `job_id` | да | options из `/get_jobs`, текст `<объект> - <должность>` |
| Рекомендатель | `text` | `referral` | да | кириллица, пробел, дефис; 3..150 символов |
| ФИО кандидата | `text` | `name` | да | кириллица, пробел, дефис; 3..150 символов |
| Пол | `radio` или `select` | `gender` | да | `Мужской`, `Женский` |
| Телефон | `text`, subtype `tel` | `phone` | нет | пусто разрешено; если заполнено, нормализовать российский номер |
| Дата рождения | `date` | `age` | да | не позже сегодняшней даты; рекомендуется проверка возраста по требованиям вакансии |
| Дата прибытия | `date` | `date_on_object` | да | не раньше сегодняшней даты, если бизнес не требует прошлые даты |
| Гражданство | `select` | `residence` | да | `Россия`, `Беларусь`, `Киргизия`, `Казахстан` |
| Комментарий | `textarea` | `comment` | нет | до 3000 символов |

После submit:

1. Выполнить server-side validation.
2. Если есть ошибки, вернуть JSON:

```json
{"errors": {"name": "Введите ФИО кириллицей"}}
```

или общий error:

```json
{"error": "Не удалось получить список вакансий. Попробуйте позже."}
```

3. Если данные валидны:
   - вызвать `/create_app`;
   - вызвать `/set_app` с заполненными полями, но без `submitted=true`;
   - сохранить flow/session: `mattermost_user_id`, `channel_id`, `application_id`, `state=awaiting_documents`;
   - отправить пользователю сообщение с карточкой анкеты и инструкцией по документам.

### 6.4 Загрузка документов

Interactive Dialogs не поддерживают upload input, поэтому документы загружаются отдельным шагом.

После создания черновика бот пишет в личный диалог с пользователем:

```text
Анкета создана. Прикрепите фото документов кандидата сообщениями в этот чат.
Когда все документы загружены, нажмите "Закончить загрузку".
```

Кнопки:

- `Закончить загрузку`;
- `Очистить документы`;
- `Отменить анкету`.

Обработка сообщений пользователя в состоянии `awaiting_documents`:

1. Если сообщение содержит `file_ids`, скачать каждый файл через Mattermost API.
2. Проверить тип файла:
   - разрешить изображения `image/jpeg`, `image/png`, `image/heic`, если Mattermost позволяет скачать исходник;
   - разрешить PDF опционально только если backend корректно принимает содержимое как photo. Если backend ожидает именно изображения, PDF отклонять сообщением.
3. Проверить размер файла: лимит задается `MAX_DOCUMENT_BYTES`, default 10 MB.
4. Закодировать bytes в base64.
5. Отправить `POST /add_app_photo {"application_id": "...", "photo": "<base64>"}`.
6. Увеличить счетчик документов в session.
7. Ответить: `Документ добавлен. Загружено: N.`

Если пользователь отправил текст без файлов в этом состоянии, бот отвечает краткой инструкцией и повторяет кнопки.

При `Очистить документы`:

- вызвать `/clear_app_photo`;
- сбросить счетчик в session;
- сообщить, что документы очищены.

При `Закончить загрузку`:

- получить анкету через `/get_app`;
- проверить, что `photo_ids` непустой или локальный счетчик > 0;
- если документов нет, вернуть предупреждение и не завершать шаг;
- показать карточку предпросмотра с кнопками `Отправить анкету`, `Редактировать`, `Загрузить документы заново`, `Отменить`.

### 6.5 Предпросмотр и отправка

Карточка анкеты:

```text
Анкета кандидата

Должность: <объект> - <должность>
ФИО рекомендателя: <referral>
ФИО кандидата: <name>
Пол: <gender>
Телефон: <phone или Не указан>
Дата рождения: <DD.MM.YYYY>
Дата прибытия: <DD.MM.YYYY>
Гражданство: <residence>
Документы: <N> шт.
Комментарий: <comment или Не указан>
```

При `Отправить анкету`:

1. Получить актуальную анкету.
2. Проверить обязательные поля и документы.
3. Вызвать `/set_app`, добавив:
   - `user_id = surrogate_user_id`;
   - `submitted = true`;
   - `comment = ""`, если комментарий пуст.
4. Очистить session пользователя.
5. Сообщить: `Анкета отправлена.`
6. Показать кнопки `Добавить кандидата`, `Список кандидатов`.

### 6.6 Редактирование

Кнопка `Редактировать` открывает Interactive Dialog с теми же полями, предзаполненными текущими значениями.

После submit:

- снять `submitted`, если оно есть, только для редактируемых черновиков или отклоненных анкет;
- сохранить новые поля через `/set_app`;
- вернуть к шагу предпросмотра.

Кнопка `Загрузить документы заново`:

- вызвать `/clear_app_photo`;
- перевести session в `awaiting_documents`;
- показать инструкцию загрузки.

Кнопка `Отменить анкету`:

- если анкета еще не отправлена, вызвать `/delete_app`;
- очистить session;
- показать главное меню.

## 7. Session/state management

Нужен локальный state store в памяти процесса, потому что сценарий создания растянут между dialog submit, загрузкой файлов и button actions.

Требования:

- хранить state только в памяти процесса, без SQLite, Redis, файлов и дополнительных внешних зависимостей;
- TTL flow: 24 часа;
- при рестарте контейнера активные незавершенные сценарии могут быть потеряны, это допустимое ограничение текущего этапа;
- при истечении TTL бот должен уметь создать новую анкету или продолжить по application id из открытой кнопки.

Хранимые поля:

- `flow_id`;
- `mattermost_user_id`;
- `surrogate_user_id`;
- `channel_id`;
- `team_id`;
- `application_id`;
- `state`: `awaiting_documents`, `preview`, `editing`;
- `jobs`: краткий cache вакансий для dialog submit;
- `document_count`;
- `created_at`, `updated_at`.

## 8. Архитектура кода

Рекомендуемая структура:

```text
src/bot/
```

### 8.1 `friend_api.py`

Класс `FriendApiClient`:

- `create_app() -> str`;
- `get_app(application_id: str) -> dict`;
- `set_app(application_id: str, data: dict) -> None`;
- `delete_app(application_id: str) -> None`;
- `add_app_photo(application_id: str, content: bytes) -> None`;
- `clear_app_photo(application_id: str) -> None`;
- `get_app_photo(application_id: str) -> dict`;
- `get_user_apps(user_id: int) -> list[dict]`;
- `get_jobs() -> list[dict]`.

Использовать `httpx` или `requests`. Предпочтительно `httpx` с timeout.

Все ошибки API приводить к доменным исключениям:

- `FriendApiError`;
- `FriendApiUnavailable`;
- `FriendApiValidationError`, если backend вернул error status.

### 8.2 `validators.py`

Функции:

- `validate_cyrillic_name(value: str) -> bool`;
- `normalize_ru_phone(value: str) -> str | None`;
- `parse_mm_date(value: str) -> str`;
- `validate_application(data: dict) -> dict[str, str]`.

Телефон:

- пустая строка допустима;
- принимать `8XXXXXXXXXX`, `7XXXXXXXXXX`, `+7XXXXXXXXXX`, форматированные варианты с пробелами, скобками, дефисами;
- нормализовать в `+79XXXXXXXXX`;
- если номер не российский, пользователь должен оставить телефон пустым и указать номер в комментарии.

### 8.3 `formatting.py`

Функции:

- `format_application_card(app: dict) -> str`;
- `format_application_list_item(app: dict) -> str`;
- `format_status(app: dict) -> str`;
- `format_job(job: dict) -> str`;
- `date_api_to_human(value: str) -> str`.

### 8.4 `mattermost_files.py`

Функции:

- получить metadata файла по `file_id`;
- скачать bytes файла;
- определить MIME/расширение;
- при необходимости загрузить PDF из `pdf_base64` обратно в Mattermost как attachment к посту.

## 9. Конфигурация

Расширить `Settings`:

```text
APP_LOG_LEVEL=INFO
WEBHOOK_PUBLIC_URL=https://public.example.com
WEBHOOK_PUBLIC_PORT=8579
WEBHOOK_HOST_PORT=8579

FRIEND_API_BASE_URL=http://snp-back:8000
FRIEND_API_KEY=...
FRIEND_API_TIMEOUT_SECONDS=10

FLOW_TTL_HOURS=24
MAX_DOCUMENT_BYTES=10485760
ENABLE_ACCESS_CHECK=false
```

`WEBHOOK_PUBLIC_URL` должен быть полным публичным origin без завершающего slash. Если порт нестандартный и доступен публично, webhook URL формируется как `<WEBHOOK_PUBLIC_URL>:<WEBHOOK_PUBLIC_PORT>/hooks/...`. Лучше реализовать helper, который корректно не добавляет порт, если `WEBHOOK_PUBLIC_URL` уже содержит порт или если порт 443/80.

Важно: Mattermost сервер должен иметь сетевой доступ к webhook URL бота. Для локальной ручной проверки можно использовать tunnel, но production deployment должен использовать публичный HTTPS endpoint или доступный из сети Mattermost internal endpoint.

Если для разработки, генерации, сборки, проверки конфигурации или разовых служебных команд нужно запускать Python-код, команды должны выполняться в виртуальном окружении проекта `venv/`. Не использовать глобальный Python и не устанавливать зависимости глобально.

## 11. UX и тексты

Все пользовательские тексты на русском.

Ошибки должны быть понятными:

- Friend API недоступен: `Не удалось связаться с сервисом анкет. Попробуйте позже.`
- нет вакансий: `Сейчас нет доступных вакансий для удаленного подбора.`
- невалидное ФИО: `Введите ФИО кириллицей, можно использовать пробелы и дефисы.`
- невалидный телефон: `Введите российский номер или оставьте поле пустым, а иностранный номер укажите в комментарии.`
- нет документов при завершении: `Добавьте хотя бы один документ перед отправкой анкеты.`
- файл слишком большой: `Файл слишком большой. Максимальный размер: <N> МБ.`
- неподдерживаемый тип: `Этот тип файла не поддерживается. Прикрепите фото документа.`

Сообщения после действий лучше делать ephemeral, если mmpy_bot/driver позволяет ответить ephemeral на action event. Если нет, использовать обычные посты и не блокировать реализацию.

## 12. Ограничения и решения

1. **Нет upload поля в Interactive Dialogs.**
   Решение: dialog собирает анкетные поля, документы загружаются отдельными сообщениями с вложениями.

2. **Backend ожидает Telegram-like numeric id.**
   Решение: стабильный числовой surrogate id из Mattermost user id.

3. **Авторизацию временно нужно опустить.**
   Решение: не применять `/get_facility_binds` для ограничения доступа; все пользователи видят все вакансии удаленного подбора.

4. **Локально полный Mattermost webhook сценарий может не запускаться.**
   Решение: подготовить проект к деплою и описать настройку публичного webhook URL.

5. **Interactive Dialog option list может быть длинным.**
   Решение: для первой версии использовать статический `select`. Если возникает ошибка из-за большого количества вакансий, попробовать сократить количество вакансий и попробовать заново, и так сокращать, пока не будет ошибки.

## 13. Acceptance Criteria

Функционал считается готовым, если:

- личное сообщение `!start` открывает главное меню акции;
- бот игнорирует сообщения вне личного диалога;
- `Список кандидатов` получает и отображает анкеты текущего Mattermost пользователя через Friend API;
- можно открыть карточку анкеты и увидеть все ключевые поля;
- `Добавить кандидата` открывает Mattermost Interactive Dialog с полями анкеты;
- submit dialog валидирует данные и создает черновик анкеты во Friend API;
- после dialog бот переводит пользователя на шаг загрузки документов;
- пользователь может загрузить один или несколько документов обычными Mattermost вложениями;
- `Закончить загрузку` показывает предпросмотр;
- `Отправить анкету` выставляет `submitted=true` и `user_id=surrogate_user_id`;
- можно отменить незавершенную анкету;
- можно очистить и загрузить документы заново;
- проект готов к деплою через Docker Compose;
- README содержит инструкции настройки публичного webhook URL;
- все Python-команды, если они нужны, описаны через запуск в `venv/`.

## 14. Не входит в текущий этап

- аутентификация и авторизация пользователей;
- ограничение вакансий по объектам пользователя;
- админский интерфейс;
- обработка решений по анкетам (`mark_apps`);
- синхронизация вакансий/доступов;
- полноценный web UI вне Mattermost;
- миграция backend API.
